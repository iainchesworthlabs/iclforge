ICL Forge is a clean-room AC-3, E-AC-3, AC-4 and Dolby Atmos codec, written from the published
standards in C++23, a TrueHD and MLP codec written from a specification the project's owner
supplied, and the applications built on them.

| Component | What it is | Docs |
|---|---|---|
| **The library** — `iclforge::<library>` | Encodes and decodes AC-3 and E-AC-3, including Atmos objects through JOC, decodes and encodes AC-4 and TrueHD, and decodes MLP. Includes container, metadata, quality, and platform-audio libraries, with C, Python, Rust, and WebAssembly interfaces that decode and encode AC-4 as well as AC-3 and E-AC-3 (TrueHD is in the C interface only so far). | [Library](docs/library/index.md), [capabilities](docs/library/capabilities.md) |
| **Forge** — `forge` + `forge-gui` | CLI and GUI for encoding, decoding, inspection, quality checks, and live audio. `forge` reads and writes AC-4, and so does the GUI: its QC, player, and object pages read it, and its encoder page and Objects tab write it, objects included; substreams, presentations, and the other layouts stay with the command line. `forge` also decodes, inspects and wraps TrueHD and MLP and encodes TrueHD; the GUI does not open, play, check or encode either. Both build AC-3 and E-AC-3 karaoke streams, the GUI in a Karaoke flow. | [Forge](docs/forge/index.md), [CLI](docs/forge/cli/index.md), [GUI](docs/forge/gui/index.md) |
| **Crucible** — `crucible` | Captures desktop applications separately and positions them in an Atmos scene. Runs on Windows and Linux; macOS code builds in CI but has not run with audio hardware. It uses the AC-3, E-AC-3 and Atmos codec only, so it has no AC-4 and no TrueHD. | [Crucible](docs/crucible/index.md), [install](docs/crucible/install.md) |
| **Hearth** — `hearth` | Plays streams through speakers, a receiver, or network sinks. The desktop player decodes for local outputs, passes AC-3 and E-AC-3 to a receiver chosen in its output picker, plays to network sinks, plays AC-4, and has a Karaoke page with timed lyrics and a microphone. The ESP32-S3 and ESP32-C6 sinks play in Sendspin groups on hardware; an ESP32-P4 or ESP32-S3 sink built with the AC-4 decoder takes AC-4 in a group, and the published sink images have that decoder off. Hearth for Android is a sink for Android TV that passes AC-3 and E-AC-3 to a receiver; it is built from source and has no release package. Hearth does not play TrueHD or MLP. | [Hearth](docs/hearth/index.md), [user guide](docs/hearth/desktop-player.md), [Android](docs/hearth/android.md), [Karaoke](docs/karaoke/index.md) |

The AC-3, E-AC-3, AC-4 and TrueHD codecs link no other codec library, FFmpeg included. The FFmpeg
command-line tools, and a librempeg build for AC-4, are used during development as independent
decoders to check output against; the build does not depend on them. Hearth's Sendspin transport
links libFLAC and Opus for the audio formats Sendspin itself defines.

**Standards and trademarks.** "Dolby", "Dolby Digital", "Dolby TrueHD" and "Dolby Atmos" are
trademarks of Dolby Laboratories. This project implements the openly published standards — ATSC
A/52:2018 (of which E-AC-3 is normative Annex E), ETSI TS 102 366, ETSI TS 103 420 and ETSI TS
103 190 (AC-4) — and is not affiliated with, endorsed by, or certified by Dolby Laboratories.
TrueHD and MLP have no openly published standard: that codec is written from a specification
supplied by the project's owner ([the plan](planning/truehd.md#sources-and-what-they-are) says what it is
and how the code is checked).
Code and documentation use the technical names AC-3, E-AC-3, AC-4 and TrueHD. Whether the patents reading on
these formats matter for your use is your problem to assess, not something this project
resolves.

**Status.** The API is not stable — releases so far are 0.x betas; the Latest release badge
above shows the current one, and [CHANGELOG.md](CHANGELOG.md) records what each contains.

**Names.** The family was called AC3Forge, and its programs `ac3cli`, `ac3gui`, `ac3hearth` and
`ac3crucible`, up to the pre-release 0.10.0-beta.1. [Renamed](docs/renamed.md) gives the old name
and the new one of every program, library, package and setting, for someone who installed a
pre-release or built against one.

**CI.** A pull request runs a gate: the static checks, then a Linux GCC build with every test and
the gold-reference gate. The merge queue runs the gate again on the merged tree, with the Qt GUI
built, and adds Windows MSVC and, for a change under `src/`, a speed and a heap-churn comparison
against the commit the entry is queued on. After a merge, one run at a time builds and tests the
other compilers and platforms (Linux Clang and arm64, Windows clang-cl, macOS), and a nightly run
adds the sanitizers, coverage, the ABI gate and the FFmpeg validation. `Branch Name`,
`CI Status` and the dependency review are the required checks. The stages are in
[CI for many agents](docs/ci-agentic.md); toolchain versions and what each leg covers are in
[Verified configuration](docs/building.md#verified-configuration); what has run on real hardware
is in [Where it runs](#where-it-runs).

**Also in the tree:** **Shield Atmos Demo** (`apps/demos/android/`) streams live, controller-driven
Atmos object motion out an NVIDIA Shield's HDMI passthrough to a real AV receiver, sideload-only
— see [docs/platforms/android.md](docs/platforms/android.md) — and the **browser demos**
(`apps/demos/wasm/`) decode and encode AC-3 and E-AC-3 in a page over the library compiled to
WebAssembly; the AC-4 module beside them has no demo page. Both demonstrate the library rather
than being products of their own.

## Limits

**Object playback in Dolby decoders.** Dolby's decoder requires a keyed authenticity tag before
it reconstructs the objects of an E-AC-3 Atmos stream. This project does not ship a key. An
operator with a key can [sign](docs/library/signing.md) a stream; otherwise Dolby's decoder plays
its 5.1 bed.

**Bit-rate modes.** AC-3 is constant bit rate because its frame size is selected from a fixed
table. E-AC-3 supports constant and variable bit rate, and AC-4 constant, average and variable.

**Limits of independent checking.** Enhanced coupling, transient pre-noise processing, and JOC
object decoding have no external reference decoder. These paths are scored with the in-repo
decoder. The AC-4 standard has no conformance clause, reference decoder or test vector with
expected output: the decoder is scored against Dolby Encoding Engine's encodes of known sources
and, where it can read them, librempeg's decoder, which does not decode AC-4's immersive element
or objects. See
[where the oracles do not reach](docs/verification.md#where-the-oracles-dont-reach) and
[Validation: AC-4](docs/verification.md#ac-4). No listening panel has been run; published quality
values are waveform or model-based measures.

**TrueHD and MLP.** The library is checked against FFmpeg's `truehd` and `mlp` encoders and
decoder, which is all the independent checking it has: no Dolby decoder, disc player or receiver has
read what it writes, and the MP4, Matroska, MPEG-TS and IEC 61937 (MAT) layouts are FFmpeg's, each
with FFmpeg as its one oracle. The Atmos substream and its object metadata, noise generator 1 and
heavy DRC are not built, and neither are the Python, JavaScript and Rust bindings, Hearth, Crucible
or the Forge GUI. See [Capabilities](docs/library/capabilities.md#truehd-and-mlp) and
[Validation: TrueHD](docs/verification.md#truehd-and-mlp).

**Content signing and protected files.** An AC-4 stream can carry a content signature that the
operator makes with their own key and certificate chain (`forge ac4-sign`, `ac4-verify`); no key or
certificate ships, and nothing is signed or checked unless asked. Nothing signs or checks a
TrueHD stream. An MP4 whose audio is protected (Common Encryption) is refused by name; nothing
decrypts it. See [Signing](docs/library/signing.md#ac-4-content-signing) and
[Common Encryption](ROADMAP.md#proposed).

**AC-4 containers and receivers.** Matroska registers no codec ID for AC-4, so `forge mkv` refuses
it; MP4, CMAF and MPEG-TS carry it. No receiver found accepts AC-4 over IEC 61937, so no AC-4 burst
has reached hardware, and WASAPI, PipeWire and Core Audio have no AC-4 passthrough format:
`forge play` and Hearth decode AC-4 to PCM.

[Validation](docs/verification.md) covers object playback and independent checking in full: what
object reconstruction means in practice, and which streams FFmpeg can check independently versus
only the in-repo decoder. Real-hardware confirmation by platform is in
[Where it runs](#where-it-runs), below.

## Building

Requires CMake ≥ 3.28, Ninja, and — for the GUI, Hearth and Crucible — a prebuilt Qt kit, never
from vcpkg: 6.5+ for the GUI, 6.8+ for Hearth and Crucible. Windows needs Visual Studio 2026
(MSVC) or clang-cl 22; Linux needs GCC 16 or Clang 22. A
[vcpkg](https://github.com/microsoft/vcpkg) checkout, which the desktop presets use (set
`ICL_VCPKG_STORE` and the first configure makes one; `VCPKG_ROOT` still works), supplies fmt and Catch2, the libraries of the default Hearth build, and Boost and Tracy
for the opt-in `adm` and `profiling` features. Configured without a preset, fmt and Catch2 fall
back to a `FetchContent` build from source, and Hearth needs `-DICLFORGE_BUILD_HEARTH=OFF`
unless its libraries are installed another way.

```bash
cmake --preset config-windows-msvc-debug
cmake --build --preset build-windows-msvc-debug
ctest --preset test-windows-msvc-debug
```

Linux follows the same shape (`config-linux-gcc-debug`, etc.), with the GUI opt-in via
`-DICLFORGE_BUILD_GUI=ON` rather than on by default. See
[Quick start](docs/quickstart.md) for the shortest path and
[Building from source](docs/building.md) for the rest — the full preset list, building without
Qt, packaging, and per-platform notes. Cutting a release is covered in
[docs/releasing.md](docs/releasing.md).

## Using it

```bash
forge encode in.wav out.ac3 448 couple
forge ac4-encode in.wav out.ac4 192
forge decode out.ac4 out.wav
```

`forge`'s commands cover encoding, decoding, muxing, inspection, QC and live capture, for AC-3,
E-AC-3 and AC-4, and decoding, inspection, muxing and encoding for TrueHD (`forge truehd-encode`, and `truehd-atmos` for a provisional Atmos stream);
run it with no arguments for the full listing.
`forge-gui` is a Qt Quick front end over the same library: file and live-capture encoding, a plan
view for placing objects, channel-level metering, QC, a stream player, an object inspector, a
Karaoke flow and project files.
AC-4 works in file encoding (objects included), QC, the player and the inspector, and is refused
in a live session. The pair is [Forge](docs/forge/index.md).
For the C++ API — two headers and about a dozen lines to encode a frame — see
[Quick start](docs/quickstart.md) or [Library conventions](docs/library/index.md).

## Validation

Quality is measured, not asserted, and checked six independent ways — a normative in-repo
decoder, FFmpeg as an external oracle, independent Python transcriptions of the spec, Dolby's own
tooling, fuzzing in both directions, and an encoder/decoder mirror self-check — all
platform-independent, since every coding decision Forge or Crucible makes is a call into
`iclforge::ac3`, or into the AC-4 library for AC-4. What each check reaches and where it runs out:
[Validation](docs/verification.md). AC-4 is checked against Dolby Encoding Engine's streams,
MediaInfo's readings, librempeg's decoder and a second transcription of its syntax:
[Validation: AC-4](docs/verification.md#ac-4). TrueHD is lossless, so FFmpeg's strict decode of
what the library writes, and of what FFmpeg's encoders write, is held to the source sample for
sample: [Validation: TrueHD](docs/verification.md#truehd-and-mlp).
The quality numbers themselves — gated SNR and ViSQOL MOS-LQO trends, and a release-by-release
comparison against FFmpeg and Dolby DEE — live on [Quality trend](docs/quality-trend.md) and
[Landscape](docs/landscape.md) instead of as a snapshot here that could drift stale.

Validation runs both ways. Every release also publishes a
[conformance vector set](docs/conformance-vectors.md): 60 AC-3, E-AC-3 and Atmos streams covering
each coding tool, layout and sample rate this encoder produces, with the source PCM, expected
decode hashes and a manifest saying which of them FFmpeg can and cannot read — so another
implementation has something concrete to test against. The set has no AC-4 or TrueHD streams. No free ATSC
or ETSI conformance bitstreams exist publicly.

Before linking the decoder against bytes from the internet, read the
[threat model](docs/threat-model.md): what is trusted and what is not, the memory-safety posture
and where the raw-pointer boundaries are, the per-access-unit resource limits, and the gaps.

```
libs/render/     iclforge::render — the room's layout, routing, the bed and object renderer and the

libs/ac4/        iclforge::ac4 — the AC-4 codec, from ETSI TS 103 190-1 and -2: the sync frame, TOC and
                presentation inspector, the decoder and the encoder, laid out as libs/ac3 is (core/,
                io/, decoder/, encoder/); no iclforge::ac3 dependency
libs/truehd/    iclforge::truehd — the TrueHD and MLP codec, from the owner's specification: the
                bitstream layer, the lossless decoder and the encoder; links iclforge::base only

                + HLS/DASH), mpegts (MPEG-2 Transport Stream) and iamf (IAMF v2.0 OBU/ISOBMFF, fed
                from an E-AC-3 decode), each a writer and a reader; TrueHD rides in the first four

libs/iab/        iclforge::iab — a standalone SMPTE ST 2098-2 (IAB) bitstream reader, codec-blind

libs/capi/       iclforge_c — a plain-C11 surface over the AC-3, E-AC-3, AC-4 and TrueHD encode/decode
                cores, for bindings and callers that do not link C++23

libs/audio/     iclforge::audio — the platform audio backends: WASAPI, ALSA, PipeWire, CoreAudio,

libs/sink/       iclforge::sink — a Sendspin sink a program runs: it advertises, pairs, and hands

libs/lyrics/     iclforge::lyrics — timed lyrics: LRC, SubRip, Advanced SubStation Alpha and MIDI

libs/pitch/      iclforge::pitch — a singing voice's pitch, a reference melody and a score of one

libs/device/     iclforge::device — the logic of the ESP32 sinks that needs no SDK, so that the host

                        encoders, the AC-4 decoder), cross-compiled for arm-none-eabi and run under
                        QEMU, or built natively on the host

# A product's programs are directories of their own: <program>/{CMakeLists.txt, src/, assets/,
# tests/}, with the program's Catch2 binary and Qt Quick tests beside it (ctest -L <name>)

# Forge — the CLI and the GUI, built and packaged as one thing
apps/forge/cli/   forge — command-line front end; its tests run the built program
apps/forge/gui/   forge-gui — Qt Quick front end (QML module "ForgeGui"), its translations and
                  Linux/macOS packaging; the Qt Quick suites and the Qt-free Catch2 cases
notices/          the NOTICES.txt and LICENSE.txt each product's packages install: the fragments
                  they are assembled from (fragments/), the licence texts (licences/) and one
                  directory per product (forge/, crucible/, hearth/) that says which it ships

# Code that more than one program compiles in, each a directory with src/ and tests/ and no
# library target of its own
apps/shared/media/        the recording sink, fMP4 folder writer, container input and AC-4 encode and
                  object steps Forge's CLI and GUI compile in, and Hearth's engine in part
apps/shared/theme/        the family's look: the system theme, the typefaces, the icons and the shared
                  QML components Forge's GUI, Hearth and Crucible show
apps/shared/preferences/  the language manager and the settings migration all three programs run

# Crucible — the desktop application and its Windows driver
apps/crucible/  Crucible: the engine, the crucible-run runner, the crucible
                window (ui/, with its translations), its packaging and the spikes the plan was
                measured with. Windows and Linux run it; the macOS platform half beside them,
                under engine/src/platform/macos and ui/src/platform/macos, compiles and is
                exercised by the CI suites; the application itself has never been launched on
                a Mac
apps/crucible/windows/   the Windows-only pieces of Crucible: the IclForgeNullSink driver (MS-PL,
                separately licensed) and the VMware guest it is verified in
apps/crucible/linux/     the Linux-only tooling of Crucible: a scripted VM guest built to find the tray
                crash; not built or packaged

# Hearth — desktop player and Sendspin sinks
apps/hearth/    hearth engine, window (ui/), hearth-testsink, hearth-testserver, hearth-render,
                and Hearth for Android (android/), a Gradle project of its own

# beside those — demonstrations of the library, not products of their own
apps/demos/android/   Shield Atmos Demo — Android TV app, live Atmos object motion over HDMI
apps/demos/wasm/      the browser demos, decode and encode, over iclforge::ac3 compiled to WASM, and the
                AC-4 module

# shared, owned by none of them
cmake/          toolchains, Qt/CPack/sanitizer/coverage modules, vcpkg triplet overlays
assets/         the app-icon source: one procedural mark, plus a hand-authored SVG for the
                WASM favicon; every .ico/.icns/.png/mipmap in the tree is generated from it
testdata/       the golden vectors more than one project's tests read - the programme audio, the
                AC-4 streams and their syntax digests, the DEE baseline, the pinned bitstream
                hashes - generated by the scripts in tools/ (see their headers)
tests/          what is not one project's: support/ (iclforge::test_support, what every test
                binary links) and performance/; a library's own tests are in libs/<name>/tests
                and a program's beside it, a binary each (ctest -L <name>)
tools/          Python: table/fixture generators and the published conformance vector
                set (generators/), correctness checks and the gold-reference gate
                (checks/), independent reference implementations (references/),
                CI-only orchestration - the PR gate's planner, trend appenders, the codec
                matrix, the FFmpeg quality race, main-health (ci/); the listening-test
                apparatus (listening/), release scripts (release/), the sink firmware tools
                (hearth/), the ESP-IDF component packer (packaging/), the aiosendspin
                interoperability scripts (sendspin/) and the fuzzing scripts (fuzz/)
requirements/   pip-compile --generate-hashes locks for the CI Python jobs: lint, coverage,
                docs, ffmpeg-validate and the wheel tests
packaging/      vcpkg port, winget manifest, Conan recipe (staged, pending upstream submission);
                Homebrew formula/cask (each release copies them to the live tap)
docs/           the site source — see Documentation below; docs-snippets/ holds the generated
                tables it includes, and overrides/ its home page template
planning/       design proposals and phase plans, not published on the site
```

The standards documents are not redistributed; `spec/` is gitignored. See
[docs/building.md](docs/building.md#the-standards-documents) if you need to re-run the table
generators in `tools/`.
