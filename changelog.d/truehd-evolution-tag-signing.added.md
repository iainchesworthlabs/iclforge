**TrueHD evolution frames can be signed with your own key.** `iclforge::truehd::signing` writes and checks a keyed HMAC-SHA-256 tag in the `evo_protection()` field of the evolution frame that carries a TrueHD stream's object metadata. The tag covers the whole access unit (the major sync, the header, the directory and the substreams as well as the object metadata) with the protection fields, the fill, the padding and the parity byte left out, and signing changes no length: `sign_evolution_unit`/`_stream`, `verify_evolution_unit`/`_stream` and the keyring forms, `has_evolution_tag` (answered without a key), and `gate_evolution_stream`, which removes the object layer from every unit whose tag does not verify so the stream plays as its bed with no re-encode and has no failing frame left. The tag is one byte in the streams observed, so it is accepted by a wrong key about once in 256 units: it detects tampering, it does not authenticate. `forge metadata` warns when a channel-meaning edit has broken tags that were there. `forge metadata <in> <out> sign-objects signing-key=<path>` signs, `forge decode <in.thd> <out.wav> verify-objects` and `gate-objects` check (repeat `signing-key=` for a keyring), and `forge probe` reports how many evolution frames carry a tag. Nothing is checked unless asked for. This is iclforge's own scheme, not observed in any Dolby stream and not an interoperability claim: the library holds no key, TrueHD spec §16.3.3 still holds, and a licensed Dolby decoder holds other keys and will not accept these tags as Dolby-authentic. See [Object signing](docs/concepts/object-signing.md).
