**The block header reads `new_guards` only while bit 0 of `param_presence_flags` is set, and the loop over the channels' parameters is always read.** Before, the decoder and the encoder read and wrote `new_guards` in every block and skipped the channel loop when bit 0 was clear, so a stream that clears bit 0 (the Dolby decoder reads such streams, and so does an independent decoder) was misaligned from its next block on. `data_check_present` now follows TH spec §8.1: `block_data_bits` counts the sample data and not its own 16 bits, and the block header CRC (polynomial 0x1D, initial value 0xA2, over the bits of `block_header()`) is checked in strict mode.
