**macOS passthrough refuses a MAT content rate it has no link for before it looks for a device.** `PassthroughSink::start()` on Core Audio went on to search for an output and answered with an unrelated error for a rate such as 32 kHz; it now returns `PassthroughError::kFormatRejected` as the ALSA, Windows, PipeWire and Android backends do. The `passthrough: MAT at a content rate it has no link for` test had failed on the macOS LLVM leg since the MAT path was added. Not run on a Mac by hand.
