The Python TrueHD reference decoder (`tools/references/truehd_syntax.py`) now hands each substream the rows the substream before it decoded *before* that substream's matrices, as the library's decoder and FFmpeg do. It used to carry the matrixed rows on, which made it decode a TrueHD Atmos bed with matrices in more than one substream (the object downmix chain's) to different samples and fail the stream's own lossless check; the "TrueHD Atmos encoder, objects against the reference and the bed against FFmpeg" CI step failed on it. The encoder's output was right: forge and FFmpeg 8 agree on it.
