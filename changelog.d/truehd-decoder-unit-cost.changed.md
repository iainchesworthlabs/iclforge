**The TrueHD / MLP decoder spends about 19 % less time on each access unit.** An access unit of a 5.1 stream decodes in 3.49 microseconds where it took 4.29, one of a 7.1 stream in 5.0 where it took 6.2 (iclforge-bench `truehd_51_decode` and `truehd_71_decode`, median of 7 runs, MSVC Release on a Ryzen 9 5950X, two base/new pairs within 1 % of each other). The decoder no longer allocates while it decodes (iclforge-membench `allocs_per_frame` was 2.35 for stereo, 4.69 for 5.1 and 7.23 for 7.1, and is 0): a text trace of each block's position, which only the object substream's error report reads, was being built for every substream, and the state of a substream was rebuilt on the heap at every restart header. The substream CRC now takes eight bytes a step and the parity a machine word, so the pair of checks costs 182 ns for a 5.1 access unit where it cost 540 ns; the block header CRC takes whole bytes. The tables add 2 KB of constant data. The block header is read into one that the decoder keeps and no longer returned and copied, which takes some 16 KB off the stack of the decode path (MSVC x64 frames: 18 KB of `decode_segment`, `read_block_header` and `read_matrices` down to 2 KB) at the cost of 5.4 KB of heap. Not one decoded sample or one check's verdict changes: every fixture decodes to the same WAV, with the same exit code and report, before and after. The throughput on the ESP32 boards, where a 5.1 stream decodes at 1.03 to 1.13 of real time on the S3, is not measured.
