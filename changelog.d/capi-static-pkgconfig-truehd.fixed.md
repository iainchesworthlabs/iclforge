**The C API's static `pkg-config` file now names the TrueHD archive, so `pkg-config --static --libs iclforge-c` links in a TrueHD build.** `libiclforge_c_static.a` holds the TrueHD decoder and encoder entry points, which call into `libiclforge_truehd_static.a`, but the `iclforge-c` package did not require `iclforge-truehd`, so a C or C++ consumer linking the installed SDK statically got undefined `iclforge::truehd::` symbols. The release run's SDK-consumer check caught it on the clang leg.
