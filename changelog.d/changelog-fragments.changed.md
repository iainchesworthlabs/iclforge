**Changelog entries are one file each, in `changelog.d/`.** A pull request no longer edits `CHANGELOG.md`, where every entry went to the top of `## [Unreleased]` and two pull requests landing together collided; it adds `changelog.d/<slug>.<type>.md`, the static job of `PR Gate` fails one that edits the file or misnames a fragment, and the release assembles the fragments with `tools/release/changelog_tool.py assemble` (`docs/releasing.md`, step 5). `changelog_tool.py extract` turns the entry a branch already wrote in `CHANGELOG.md` into a fragment. What is under `[Unreleased]` today stays as written and is carried into the next release.
